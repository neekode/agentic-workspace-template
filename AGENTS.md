# Shared working agreement

Read the selected project's AGENTS.md and current README or work queue before
work. Keep common rules here once; children add domain constraints. Report missing
instructions. User direction and tool-enforced higher-priority instructions govern.
The starter supplies only AGENTS.md. During selected-tool setup, create a minimal
native loader if needed; do not precreate configuration for unused tools.

## Research and reuse

This starter teaches CLI-based workflows. Adapt explanations to the user's
experience, editor, chosen CLI and goal; help them understand and verify commands.
Recommend additional tools and integrations only for a task that needs them.

Define the job and required evidence before choosing an implementation. Check
existing applications, connected tools, repository utilities and prior research;
consult current official docs, packages, plugins, scripts, APIs and MCPs as needed.
Research once at the capability level and reuse still-valid findings. Prefer reuse,
then configuration, then a small extension. Explain an evidenced gap before custom
code. Use catalog, cached or batch capabilities for repeated work where suitable.
See [integration guidance](docs/tools.md#mcps-and-external-integrations).

## Scope and coordination

Inspection and proposals are read-only. Implement only the requested scope and
preserve unrelated work and staging. Research or task capture grants no install,
account connection, purchase, deployment or publication authority. Honor existing
approval; ask only when a consequential choice or scope gap blocks progress.

Assign each active writer a named target. Avoid overlapping edits and concurrent
Git operations in one checkout. Use sequential review or isolated worktrees when
needed. Do not assume separate sessions share context. See the
[workflow reference](docs/workflow.md) for coordination and session requests.

## Keep the workspace lean

Reuse the existing README, queue or product plan. Next / Backlog / Waiting is an
optional small-project default; omit empty sections. Keep tasks and durable results
in one home. Discussion stays in conversation until recording is requested. Do not
create dated reports, duplicate policies or a new folder for each session.

Organize by responsibility; evaluate consolidation and removal before moving files.
Repos hold maintained source, docs and deliberate assets. Reproducible processing
material can use ignored cache with an owner and retirement condition. Preserve
unique work and needed recovery; cache placement alone proves nothing disposable.
Use existing history and inputs before making copies. No automatic full backups.
Propose reductions through `trim` and apply them after approval of the reviewed set.

## Verification and privacy

Use checks appropriate to the change and report their limits. Distinguish file
checks, live integration behavior and human acceptance. Keep one maintained result
and retire this task's authorized disposable output. A configured connector is not
proof that the intended operation works.

Keep credentials and private household/account data out of published examples.
Track only nonsecret tool configuration. Ignore rules do not remove already-tracked
files or restrict an assistant's access. Do not stage, commit, push or publish unless
requested. Template maintenance lives in [now.md](now.md).
